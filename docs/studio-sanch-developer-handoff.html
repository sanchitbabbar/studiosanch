01 · Overview

What this website is

Studio Sanch is a bilingual, editorial luxury website combining a cinematic studio presentation, couture and production services, a request-led boutique, artwork presentations, and French legal information. It is exported as static files and does not use a conventional checkout.

Hosting model
Commercial model: visitors submit an enquiry or consultation request. Studio Sanch responds with a quotation (“devis”). There is no live card checkout on the current site.

02 · Architecture

Hybrid application structure

The repository contains two systems that share assets and styling. A developer must preserve this distinction unless undertaking a deliberate migration.

Next.js / React routes

Homepage, productions, terms, boutique, artworks, and dynamic product pages live under app/. React provides state, language context, animation, product data, and reusable header/footer components.

Standalone HTML routes

About, Atelier, Haute Couture, contact, appointments, accessories, legal and related French pages live under public/. They use shared CSS and vanilla JavaScript.

04 · Design system

Visual language

Palette

Black backgrounds, restrained off-white text, low-opacity borders, soft grey secondary copy, and very limited warm editorial grading in photography.

#000000#e0e0e0rgba white

Typography

Montserrat is the principal interface and editorial font. Syne is reserved for selected studio headings. Letter spacing and light font weights are integral to the luxury tone.

Montserrat 300–600Syne 400–800

Interaction

Motion is slow, restrained and cinematic. Hover states increase luminosity and remain active while the pointer is present. Abrupt sliding or visibly mechanical transitions should be avoided.

Layout

Full-bleed media, generous black space, thin dividers, uppercase micro-labels, centered statements, and responsive edge-to-edge presentation on mobile.

Do not replace the site’s restrained off-white with pure white indiscriminately. Major headings were calibrated to match the SANCH logo rather than appear brighter than it.

07 · Language

English and French must remain complete

The language preference is stored in both language and i18nextLng local-storage keys. React routes use LanguageContext.tsx. Static pages use public/js/i18n.js, JSON locale files, or dedicated pages under public/fr/.

React pages

Text is selected through useLanguage(). The language panel updates state and persistence without requiring a page reload.

Static pages

French routes generally live at /fr/[page].html. Language buttons must link to the exact equivalent page, not simply the French homepage.

The website is not yet a single unified internationalization system. When adding a page, the developer must explicitly provide every visible label, button, form message, modal, cookie string, footer item and accessibility label in both languages.

08 · Boutique and private requests

Request-led, not checkout-led

Products and services are discovered through the boutique, artwork gallery, product pages, Haute Couture page and private consultation modal. The current sales process is:

Visitor selects a work or service→Request form→Studio receives enquiry→Studio issues quotation→Agreement and payment handled separately

Product source

Accessory products are maintained in app/data/accessories.ts. Each record includes ID, English/French copy, price, primary/additional images, category, visibility, availability and feature lists.

Private Collection Consultation

The Haute Couture enquiry card must display one summary heading only: Private Collection Consultation. Its behavior is implemented in public/js/purchase-inquiry-modal.js.

Do not introduce card fields or claim that the website takes payment unless a real, legally reviewed checkout system is intentionally implemented.

12 · Build and deployment

Static export contract

next.config.js uses output: 'export', trailingSlash: true and unoptimized Next images. The production build writes a deployable site to out/.

npm run build

# Expected output
out/
  index.html
  productions/index.html
  boutique/index.html
  product/.../index.html
  copied public assets and standalone HTML pages
Build quality warning: the present config ignores TypeScript and ESLint build errors. A maintainer should run npx tsc --noEmit separately and should not treat a successful export alone as complete validation.
  • Confirm all generated routes and standalone .html pages are included in the deployed artifact.
  • Confirm the host maps directory routes with trailing slashes correctly.
  • Confirm large MP4/WebM assets support byte-range requests and suitable cache headers.
  • Confirm the custom domain, HTTPS and canonical URLs after each deployment.
  • Keep Git main deployable; use feature branches for structural migrations.

13 · Quality assurance

Release checklist

  • Homepage begins in black and white; first flicker starts after seven seconds; color/monochrome layers never separate.
  • Homepage camera motion never crops the model’s head or exposes additional floor at the wrong moment.
  • Header menu opens, closes by X/backdrop/Escape and routes correctly in English and French.
  • Footer is visually consistent on every page; order is Make an Appointment, Write to Us, Language.
  • Language panel styling and persistent hover luminosity match the other footer links.
  • Every English page contains only English UI; every French page contains only French UI.
  • Boutique mobile category selection reveals the primary action without requiring an upward scroll.
  • Boutique close animation has no abrupt leftward content spill.
  • Production reel autoplays muted, loops, uses the selective monochrome version and shows its poster while loading.
  • Atelier images/videos retain original light with restrained luminosity and contrast; no unintended dark overlay.
  • All forms have labels, required validation, keyboard access, a visible success state and confirmed message delivery.
  • Privacy, Terms and Legal links appear in that order and legal identity remains available.
  • Phone number appears only where legally required, currently within legal identity.
  • Test Safari iOS/macOS, Chrome, Firefox and Edge at mobile, tablet and desktop widths.
  • Run npx tsc --noEmit, npm run build, link checks and a final visual comparison before deployment.

14 · Known risks and recommended next work

Developer attention areas

Hybrid duplication

Header, footer and language behavior exist in both React and static implementations. Changes can drift. Long term, migrate static pages into shared React components or introduce a controlled template build.

French route consistency

Some French pages are dedicated files while React pages switch copy in place. Define a single URL strategy and add route-level automated checks.

Asset weight

The media library is large. Add responsive derivatives, preload only critical media, lazy-load below the fold, and review video bitrates without modifying visual grading.

Form observability

Add real error states, delivery monitoring, spam protection and retention documentation. Never show success when the request was not received.

Build enforcement

Remove ignored TypeScript/ESLint errors after the current codebase is clean, then enforce checks in continuous integration.

Legal review

Terms, privacy, cookies and legal notices should be reviewed by qualified French counsel whenever selling process, analytics, data collection or business identity changes.
